VEHICLECONNECT QR — PERMANENT CLOUD DEPLOYMENT
==============================================

What this package does
----------------------
This version is prepared for a cloud host. The host runs Flask and MySQL online,
so the website and admin panel continue working when your PC is turned off.
It also supports Railway's MYSQLHOST / MYSQLPORT / MYSQLUSER / MYSQLPASSWORD /
MYSQLDATABASE environment variable names.

IMPORTANT: This ZIP does not itself create a public website. You must deploy it
to a hosting account and attach a persistent database. The host then gives you
a stable HTTPS domain. Do not use Cloudflare Quick Tunnel for permanent stickers.

DEPLOYMENT OUTLINE (Railway or a similar Python host + MySQL)
------------------------------------------------------------
1. Create a hosting account and a new project.
2. Add a MySQL database service to the project.
3. Deploy this folder as the web service from a GitHub repository, or use the
   host's supported ZIP/Git deployment workflow.
4. Configure the web service environment variables listed below.
5. Generate a public HTTPS domain in the host dashboard.
6. Set BASE_URL to that exact public HTTPS origin (no trailing slash).
7. Deploy/redeploy after changing BASE_URL. New QR codes will point to this
   permanent domain. Existing QR codes need to be regenerated if they were
   made with 127.0.0.1 or a temporary trycloudflare.com address.
8. Import schema.sql into the hosted MySQL database before first login.
9. Create the admin account using the host's shell/console:
       python create_admin.py
   Ensure it runs with the same production environment variables.
10. Test storefront, /health, /admin/login, customer creation, and a QR scan
    from a phone with Wi-Fi switched off (mobile data).

REQUIRED ENVIRONMENT VARIABLES
------------------------------
FLASK_SECRET_KEY = a long, random secret (at least 32 random characters)
FLASK_DEBUG = 0
BASE_URL = https://your-stable-hostname.example
MYSQLHOST = host provided by your MySQL service (or MYSQL_HOST)
MYSQLPORT = port provided by your MySQL service (or MYSQL_PORT)
MYSQLUSER = database username (or MYSQL_USER)
MYSQLPASSWORD = database password (or MYSQL_PASSWORD)
MYSQLDATABASE = database name (or MYSQL_DATABASE)

Optional payment keys should remain empty until Razorpay test mode is configured.
Never upload your .env file, database passwords, payment secrets, or admin password
to GitHub. Use the host's environment-variable settings instead.

DATABASE SCHEMA
---------------
Import schema.sql into the hosted MySQL database. Do not use your local 127.0.0.1
database settings on the cloud host; localhost there refers to the host container,
not your Windows PC.

CUSTOM DOMAIN
-------------
You can initially use the stable HTTPS domain generated by the host. To use a
branded permanent domain (recommended for QR stickers), buy a domain and connect
it in the host's custom-domain settings. A custom domain normally has a renewal fee.

PRODUCTION SECURITY CHECKLIST
-----------------------------
- Use a unique strong admin password and a random FLASK_SECRET_KEY.
- Keep debug mode off.
- Use a least-privilege database user; don't expose MySQL publicly if the host
  offers private networking.
- Review customer consent, privacy policy, and public phone-number visibility.
- Test backups and restore before taking real orders.
- Configure Razorpay only after testing the complete payment flow.
- This project has not undergone a professional security audit; don't store
  real customer data until you have reviewed and tested it.

LOCAL DEVELOPMENT
-----------------
Keep using run.py locally as before. The cloud deployment uses wsgi.py + Gunicorn.
